# 页面加载性能优化

对照基线：`61a1678`。保留代表 Run 的人工基准、最高有效指标、最新优先级，以及总览 200 条、Run 查询 1000 条的既有上限。

## 修改

- 前端侧栏、地图目录和研究/项目地图列表使用 `include_evidence=false`。列表仍保留基准名称和指标，但不再为目录显示执行完整 Run 质量检查、读取产物和笔记。API 默认保持完整证据，兼容 CLI/SDK。
- 地图详情在单次序列化内复用 Run 质量检查、证据和分支代表结果；请求结束即清除，下一次请求重新检查，不使用跨请求缓存。
- 总览代表 Run 和地图分支代表选择按 200 条分批读取，只读取身份、状态、时间及主指标所在 namespace；逐项保留最佳候选，只加载最终代表的完整 Run。仍需遍历候选，未声称数据库扫描已消除。

## 本地隔离对照

地图测试数据：59 个 Run、1 张地图、5 个节点，取预热后 5 次请求中位数。优化前后详情返回内容断言相同。

| 路径 | 修改前 | 修改后 | SQL 次数 |
|---|---:|---:|---|
| 地图列表 | 8.51 ms | 3.29 ms | 18 → 5 |
| 地图详情 | 22.12 ms | 19.12 ms | 66 → 54 |

代表选择测试：3059 个合成 Run，其中新增 3000 个各含 4 KiB 无关诊断字段；启用 tracemalloc 的 3 次测量。结果完全相同。中位耗时 119.00 → 112.62 ms；Python 峰值内存 28.06 → 0.30 MiB。此处不是生产数据库或远程网络延迟实测，生产效果仍需部署后确认。
