# WebUI 按需加载改造与验收

分支：`codex/on-demand-page-loading`。实施于 2026-09-16 至 2026-09-17。

本次修改已在本地隔离数据上验证；尚未部署到用户实际访问的 `http://127.0.0.1:8013`。隔离预览地址为 `http://127.0.0.1:8025`。生产诊断见 [改造前性能排查](performance-audit-2026-09-16.md)。

## 加载边界

| 页面或内容 | 改造后请求方式 |
|---|---|
| 全局导航 | 只加载项目标识和当前页面所属实体；展开导航才取对应研究、分支目录 |
| 总览 | 活动历史、项目分别加载，仍位于第一和第二；后续卡片进入可视区域才加载，系统信息展开后加载 |
| 项目 | 研究线每页 30 条；比较、保存搜索、设置展开后加载；近期 Run 按可视区域加载 |
| 研究线 | 默认研究地图；分支与 Run、评审、历史标签仅挂载当前内容 |
| Run 查询 | 服务端筛选和排序，每页 50 条；跨页选择保留；完整配置列由用户展开后才加载 |
| Run 详情 | 结果、指标、事件、产物、配置、快照和笔记分开请求；事件与笔记每页 100 条；编辑和克隆展开时取配置 |
| 研究地图 | 先取布局所需的轻量节点与指标，不返回重复 tree；选中节点后再取证据、质量检查、笔记和产物 |
| 比较与搜索 | 保存的集合按项目分页；创建比较时才取候选 Run；全局搜索仅在打开时请求服务端 |
| 图表资源 | ECharts 动态加载，构建 HTML 不再提前 modulepreload ECharts |

完整地图仍需要全部节点的轻量拓扑来布局。项目导航仍包含项目标识集合，但不包含其下全部研究、分支和 Run 内容。已有 CLI/SDK 接口保留；新读模型位于 `/api/v1/ui/*`，沿用既有鉴权。

## 刷新、计算和传输

- 请求按 URL 与认证身份合并，慢请求完成后再安排下一次轮询。隐藏浏览器标签暂停轮询，过期响应不写入新页面。
- WebUI 接口返回 ETag，内容不变时返回 304；前端保持原对象，地图选中节点、折叠、缩放、平移不因轮询重置。304 仍需要服务端查询并生成内容摘要，并不是完全免计算。
- 地图初次加载不执行全部节点的曲线质量校验；直接绑定 Run 和分支代表批量查询。选中节点的展示质量提示使用 30 秒、128 项上限缓存；指标、Run、产物及本地文件版本变化参与失效判定。写入、结束及比较的原有质量门仍实时执行。
- 代表 Run 只扫描当前请求范围，保留人工指定 → 最高有效指标 → 最新的规则；没有增加跨请求的代表 Run 持久化缓存。
- 增加 Run 更新时间、创建时间和分支更新时间索引，迁移版本为 10；兼容既有数据库补建索引。旧总览按研究预先分组分支；研究搜索仅读取命中研究下的数据。
- 启用 gzip（大于 1,000 字节的响应），哈希静态资源长期缓存、HTML 重新验证。

## 可重复性能对照

本地合成数据 **3,059 个 Run、5 个地图节点**，同一数据集、顺序请求、预热后 3 次中位数；不是生产数据，也不是经 8013 的端到端加载时间。旧接口采用当前实现保留的兼容路径。

| 请求 | 中位耗时 | SQL 次数 | 未压缩响应字节 |
|---|---:|---:|---:|
| 旧完整总览 | 83.38 ms | 32 | 821,870 |
| 新导航上下文 | 2.28 ms | 1 | 346 |
| 活动历史 | 13.21 ms | 5 | 95 |
| 项目表格 | 3.93 ms | 5 | 624 |
| Run 当前页 50 条 | 8.57 ms | 7 | 41,325 |
| 旧完整地图 | 17.08 ms | 54 | 13,982 |
| 新地图结构 | 3.44 ms | 6 | 5,429 |
| 单个节点详情，缓存命中 | 5.27 ms | 9 | 1,544 |
| 未变化地图刷新 | — | — | 0（304） |

346 字节仅指导航，不是整个首页。首页还加载活动、项目及当前可见卡片。原始记录：`work/page-review/on-demand-performance.json`；脚本：`work/page-review/benchmark_on_demand.py`。合成数据的重复程度较高，其压缩率不代表生产数据。

## 验证

- 后端全套：138 passed。最后补充失败计数断言后，UI 与迁移相关 10 项再次通过。
- 前端请求测试：3 passed，覆盖进行中请求合并、304 对象身份及失败后重试。
- `npm run build` 通过；`git diff --check` 通过。
- 浏览器验证：地图多次自动刷新后 SVG 平移/缩放变换不变，选中节点保留；点击节点才出现节点详情请求。
- Run 59 条隔离数据分页为 50 + 9；第一、第二页分别选择 Run 后成功创建比较，样本、费用、配置差异均可见。测试组合含缺失结果的 Run，页面保留质量错误提示。
- 隔离 Run `分页验收 50` 从运行中取消，状态及 `run_cancelled` 事件回显，终态按钮禁用；生产记录未修改。
- 配置标签请求独立的 `section=config`，未同时请求曲线结果；全局搜索 `10bps` 返回目标 Run；研究线默认显示地图。
- 截图：`work/page-review/on-demand-overview.png`、`on-demand-compare.png`、`on-demand-map.png`。

## 部署与仍需实测的事项

1. 8013 经 SSH 转发到远程 8010；远端仓库存在未提交业务修改，部署前必须保留并合并这些修改。不能覆盖整个远程仓库。此次没有重启或迁移生产服务。
2. 已降低传输量，但原链路 65–79 KB/s 的底层原因尚未确认，也未调整 SSH 或网络配置。部署后需要固定数据复测首次进入、二次进入、地图和大规模比较的实际加载时间。
3. 主应用仍为约 607 KB 的未压缩 JS，ECharts 为约 1,054 KB 的独立懒加载资源。此次没有重构整个单文件应用为全部路由拆包。
4. 活动历史沿用已有汇总缓存及其失效语义；数据库读取量仍随规模增长。代表 Run 候选在当前研究范围内仍需扫描，超大研究线后续可基于实际测量进一步优化。
5. 当前预览使用隔离验收数据；实际用户数据规模、并发写入和真实慢网络下的体验还需要部署后验收，不能把本地耗时当作生产加速结果。
