# 关键流程设计

## 1. 流程一：普通回测记录

### 场景
研究员在一个已有 Branch 上跑新参数。

### 流程
1. SDK `bb.init()`
2. 服务端创建 Run
3. SDK 自动采集 code/env/config
4. 运行中不断 `bb.log_event()` / `bb.log()`
5. 回测结束写 `strategy.summary`
6. 上传 report / trades / positions
7. `bb.finish()`
8. Worker 生成预览
9. WebUI 更新 branch 和 compare 视图

## 2. 流程二：参数遍历

### 场景
针对同一思路扫描 `lookback x hold_days`。

### 方案
- 先创建 `Sweep`
- 每组参数生成一个 Run
- 每个 Run 都带 `sweep_id` 和 `coord_json`
- Sweep 完成后生成：
  - 参数热力图
  - 排名表
  - Pareto frontier

### 好处
参数搜索不再只是“很多孤立 run”，而是一组有结构的实验。

## 3. 流程三：突然灵感带来的分叉

### 场景
某次回测看上去不错，但你突然想到把中性化方案换掉。

### 流程
1. 在 WebUI 或 CLI 上从某个 run 创建新 Branch
2. 填写：
   - 分支原因
   - hypothesis
   - 预期影响
3. 新分支下继续创建 Run
4. WebUI lineage 图显示新支路

### 为什么重要
这正是你的核心需求：研究过程不是一条线，而是不断分叉。

## 4. 流程四：AI Agent 主导研究

### 场景
Agent 自动寻找更优参数或更优实现。

### 流程
1. `bbox search runs` 找最优 baseline
2. `bbox branch create --from-run`
3. `bbox run start`
4. 执行代码
5. 周期性 `bbox run log-metric`
6. 上传回测报告与图表
7. `bbox note add` 写结论
8. `bbox compare runs`
9. 若优于 baseline，标记候选 champion

### 设计要点
Agent 必须既能写结果，也能写“原因”和“结论”。

## 5. 流程五：离线回测后同步

### 场景
回测在无法直连服务的机器上跑。

### 流程
1. SDK 进入 offline mode
2. 本地写 queue 和 artifact manifest
3. 回测完成后，运行 `bbox sync`
4. CLI 批量把 logs 和 artifacts 同步到服务端
5. 服务端恢复完整 Run
