# 产品概述

## 1. 产品目标

`blackbox` 是一个面向量化策略研究与因子开发的实验管理系统，目标不是“存日志”，而是把研究过程结构化、可追踪、可比较、可回溯。

它同时服务三类入口：

- **WebUI**：给人使用，负责浏览、比较、追踪、复盘
- **CLI**：给 AI Agent 使用，要求非交互、稳定、结构化输出
- **SDK**：给代码使用，负责低摩擦埋点、记录指标、上传产物

## 2. 解决的问题

量化研究和常规机器学习实验管理不同，主要难点在于：

1. **实验不是线性的**  
   不是一个模型跑 100 个 epoch，而是一个 baseline 跑完后，可能因为一个新想法突然开出新分支。

2. **结果高度依赖上下文**  
   同一个策略指标，不同 universe、手续费模型、撮合方式、去极值方法、行业中性化方案下，不可直接比较。

3. **产物比日志更重要**  
   回测报告、PnL 曲线、持仓明细、交易流水、因子分层结果、IC 时序、暴露分析，经常比简单 scalar metric 更关键。

4. **AI Agent 参与研究越来越多**  
   Agent 需要一个稳定接口来：
   - 查询历史实验
   - 继承某次实验配置
   - 开新分支
   - 写入新结果
   - 比较多个候选 run
   - 记录“为什么这么改”

## 3. 设计原则

### 3.1 分支优先，而不是 step 优先

系统的最小“研究管理单元”不该是 step，而应是：

- 一个研究项目（Project）
- 一个研究对象（Research）
- 下面的多个思路分支（Branch）
- 每个分支上的多次运行（Run）

### 3.2 事件驱动，而不是 epoch 驱动

量化研究中的关键节点通常是：

- 数据准备完成
- 因子生成完成
- 去极值/标准化完成
- 中性化完成
- pre-cost 回测完成
- post-cost 回测完成
- 风险归因完成
- 结果审核完成

因此日志模型应允许按 **事件 / 阶段 / 参数坐标 / 时间轴** 记录，而不是强制用整数 step。

### 3.3 Artifact 是一等公民

下列对象应被视为一等公民：

- 回测 HTML 报告
- 收益/净值/回撤曲线
- 因子 IC 时序
- 分层收益图
- trade log / position log
- 参数搜索结果表
- notebook / markdown note
- 代码快照与配置文件

### 3.4 可复现优先

每个 Run 都应能回答这几个问题：

- 用了哪份代码
- 用了哪份数据
- 用了哪些配置
- 运行环境是什么
- 它从哪个分支、哪个 baseline 演化而来

### 3.5 Agent 友好

CLI 与 API 必须支持：

- 非交互
- JSON 输出
- 幂等写入
- 资源 ID 稳定
- 错误码可解析
- 支持查询与编排，而不只是“打印表格”

## 4. V1 范围

V1 建议聚焦以下能力：

- Project / Research / Branch / Run 核心模型
- SDK 记录 metric / event / artifact
- CLI 完整覆盖创建、查询、比较、上传
- WebUI 支持浏览、比较、追踪 lineage
- FastAPI 提供统一后端
- Postgres + 对象存储的基础持久化
- 可选本地模式（SQLite + 本地文件）

## 5. V1 非目标

V1 不建议一开始就做：

- 完整的任务调度系统
- Notebook 在线编辑
- 复杂权限系统
- 可视化拖拽式 dashboard builder
- 回测引擎本身
- 数据仓库本身

`blackbox` 是研究记录与实验管理层，不是执行引擎和行情平台。
