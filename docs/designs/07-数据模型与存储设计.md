## 2. 大小数据的存储策略

### 2.1 直接入库

适合：

- scalar metrics
- 小 event payload
- summary
- tags
- notes
- config
- 预览数据

### 2.2 只存对象存储

适合：

- 大 DataFrame
- 详细持仓/交易记录
- 大型时序
- html 报告
- notebook
- 图片
- parquet

### 2.3 混合存储

最佳实践是：

- DB 里存摘要、schema、preview
- 对象存储里存原始文件

例如一个 `trade_log.parquet`：

- DB 中存：
  - 行数
  - 列名
  - 时间范围
  - 前 20 行预览
- MinIO 中存全量文件

## 3. 索引建议

建议至少建立：

- `runs(project/research/branch/status/time)`
- `runs(tags GIN)`
- `runs(summary_json GIN)`
- `run_metrics(run_id, namespace, key)`
- `artifacts(run_id, kind)`
- `branches(research_id, parent_branch_id)`
- `run_events(run_id, sequence_no)`

## 4. 对象存储路径建议

```text
s3://blackbox/
  workspace/{workspace_id}/
    project/{project_id}/
      research/{research_id}/
        branch/{branch_id}/
          run/{run_id}/
            artifacts/{artifact_id}/{filename}
```

这样组织便于清理、备份和定位。

## 5. 去重策略

很多报告或大表可能重复上传。  
建议按 `sha256` 做可选去重：

- 相同内容只存一份 object
- artifact 记录保留多对一引用

## 6. 保留策略

建议支持项目级 retention policy：

- 原始大文件保存多久
- 失败 run 是否自动归档
- preview 是否永久保留
- 是否允许删除 raw artifact 只留 summary
